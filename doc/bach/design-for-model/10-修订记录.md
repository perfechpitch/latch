## VU 与 DTE 的任务身份改为 dsa_ids 直连

**改动日期**：2026-09-08

**改前**：三个 DSA 的 `stream_id` / `task_id` / `user_id` 一律由软件写进各自的动态参数寄存器。RV core 从自定义 CSR 读出 TS 下发的这几个值，在写 Trigger 之前用配置指令写给 DSA。

**改后**：分成两条路。DTE 与 VU 各与本核那个 RV core 之间有一条 `dsa_ids` 直连，从 CSR 直接连过去、每拍有效，DSA 在写 Trigger 那一拍采样，软件不必再写一遍；DTE 取 `streamID` / `taskID` / `userID` / `pathID` 四项，VU 只取前两项。MU 没有这条线，那一组仍由软件写进它的动态配置寄存器。

**依据**：《VU-DSA 寄存器整理》的寄存器表里没有 `task_id`，`macro_inst_trigger` 的 `STREAM_ID_OVERRIDE` 描述为“`0` = 沿用 VU-Core CSR 中自带的 Stream ID”，即身份本来就在 CSR 侧，不在 DSA 的寄存器里。

**对软件的影响**：VU kernel 与 DTE kernel 不再需要写身份寄存器，MU kernel 照旧要写。`task_id` 在 VU 这一侧没有寄存器可配，`STREAM_ID_OVERRIDE` 只改 `stream_id`，改不了 `task_id`。

**改到的位置**：

| - | - | - |
| `07-units/chip/core/vu.md` | 功能清单 F5、新增 F5a | `stream_id` 两个来源，`task_id` 只取 VU-Core CSR 那一份；那一组走 `dsa_ids` 直连 |

## VU 算力的精度口径改为 FP32

**改动日期**：2026-09-08

**改前**：VU 算力标注为“32 MAC/T（FP16 口径）”。

**改后**：改为“32 MAC/T（FP32 口径）”。数值不变，只改精度口径。

**依据**：同一份参数汇总里向量位宽写的是“1024 bit/cycle，等效每周期 32 个 FP32 或 64 个 BF16”，32 这个数按 FP32 算出来；VU 的内部计算精度只有 FP32 与 BF16 两种，没有 FP16。

**改到的位置**：

| 文件 | 位置 | 改了什么 |
| - | - | - |
| `07-units/chip/core/vu.md` | 第 7 章参数汇总 | “算力 32 MAC/T（FP16 口径）”的口径改为 FP32 |
| `05-建模参数与性能模型.md` | VU 算力那一行 | 表头“VU 算力（FP16）”改为“VU 算力（FP32）”，备注本来就写着 32 FP32 |

**没有改的位置**：

* `02-系统与部署.md` 算子表里 SiLU / dot 等的 `@FP16` 标注：那是算子输入输出的数据格式，不是 VU 算力口径。但 VU 的 CM 侧数据格式只有 FP8_e4m3 / MXFP8 / BF16 / FP32，这几处标注同样对不上，待确认后另行处理
* `05-建模参数与性能模型.md` 的“DTE 算力（FP16）”：DTE 不在本项范围内
