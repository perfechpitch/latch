# 数值与参考实现

> **文档模式：** 规格。只给规则，不含动机与取舍。
> **文档层级：** 详细实现。它只服务于 Bach 在 latch 上的重建这一件事。
> **目的：** 给写 `common/numeric/` 与 `reference/` 的实现者，定下每种数据格式的编码、每处转换的舍入、每处累加的结合顺序，以及参考实现与模型怎么共用同一份实现。两侧按同一份规则算，逐 bit 比对才有意义。

***

## 1. 逐 bit 相等的含义

模型的输出与参考实现的输出按字节比较，不留容差。要做到这一点，两侧在三处必须完全一致：每个数的编码、每次转换的舍入方向、每次多项相加的结合顺序。

这三处都不由浮点加法的数学性质保证：浮点加法不满足结合律，换一个累加顺序结果就换一个尾数。因此结合顺序是本文件的规则，不是实现者的自由。

模型与参考实现引用同一份 `common/numeric/`。参考实现不另写一套编解码与累加。

***

## 2. 数据格式

### 2.1 单个数的格式

| 名字 | 位宽 | 构成 |
| --- | --- | --- |
| `FP32` | 32 | 1 符号、8 指数、23 尾数，IEEE 754 binary32 |
| `BF16` | 16 | 1 符号、8 指数、7 尾数，即 FP32 截去低 16 位尾数 |
| `FP8_E4M3` | 8 | 1 符号、4 指数、3 尾数 |
| `FP4_E2M1` | 4 | 1 符号、2 指数、1 尾数 |
| `E8M0` | 8 | 无符号，纯指数，只表示 2 的整数次幂 |

`E8M0` 只作为块格式的 scale 出现，不单独承载数据。

### 2.2 带 scale 的块格式

一个块是连续若干个元素共用一个 scale。块内元素按低精度存，取值是元素乘 scale。

| 名字 | 元素格式 | 块长 | scale 格式 |
| --- | --- | --- | --- |
| `MXFP8` | `FP8_E4M3` | 32 | `E8M0` |
| `MXFP4` | `FP4_E2M1` | 16 | `FP8_E4M3` |
| `NVFP4` | `FP4_E2M1` | 16 | `FP8_E4M3` |

块长与 scale 格式由 MU 的算力档决定：`MXFP8 × MXFP8` 那一档 scale block 是 32 且 scale 走 `E8M0`，两档 FP4 混合精度的 scale block 是 16 且 scale 走 FP8。

scale 在存储里与数据分开放：Core Mem 的 scale 区与数据区一一映射，一个 scale 对应块长个元素；搬运时 scale 的长度按 `data_len / 32` 算。

## 3. 转换

### 3.1 扩宽是精确的

低精度转高精度不丢位，不需要舍入模式：`FP8_E4M3`、`MXFP8`、`BF16` 转 `BF16` 或 `FP32` 都是精确扩宽。带 scale 的块格式扩宽时，元素先扩宽再乘 scale。

### 3.2 窄化按 `ROUND_MODE`

高精度转低精度按 `TYPE_VL.ROUND_MODE` 舍入。发生窄化的只有三处：

| 处 | 转换 |
| --- | --- |
| LU 的 `ld.fp32.vm`，且 `DATA_TYPE` 为 BF16 | FP32 → BF16 |
| SU 的高转低写出：`st.fp8e4m3.vm`、`st.mxfp8.vm`、`st.bf16.vm` | FP32 或 BF16 → 目标格式 |
| `DATA_TYPE` 为 BF16 时标量进入向量通路 | FP32 → BF16 |

除这三处以外的通路不做窄化。

`ld.fp32.vm` 窄化的结果为 NaN 时置 `DATA_CVT_ERROR`。

### 3.3 特殊值

MU 的乘加结果为 NaN 或 Inf 时硬件做 Clamp，不阻塞流水；零输入旁路，特殊值穿透。参考实现在同一位置做同样的 Clamp。

## 4. 累加顺序

三处多项相加，各有各的固定顺序。

### 4.1 MU 的矩阵累加

单个 lane 一拍算的是

```
p    = CSA(a × b)                       按 scale block 分组累加，组内顺序固定
d    = sf_a × sf_b × p + c              c 取自上一个专家的结果，第一个专家取 0
```

两条规则：

* **先按 scale block 分组，组内累加完再跨组累加**。组内的顺序固定，两侧同序
* **scale 在组累加之后才乘**：`sf_a × sf_b × p`，不是先给每个元素乘 scale 再相加

专家之间是链式的：`C = C + (A × B) × W_ep` 这条形式不支持初始 C 加载，`c` 只能来自上一个专家在同一 lane 上的结果，因此专家的先后顺序也进入结果。参考实现按同一个专家顺序算。

`vlane` 为 2 时在 CSA 树的第 128 输入层级插旁路，部分和进 `ksplit_acc` 再合并。这一档的合并点位置同样进入结果。

### 4.2 VU 的跨元素归约

VALU1 的跨元素归约分两级：先在 LANES 内归约，再做 ⌈log2 SEG⌉ 级两两累加。

参考实现按同一个两级结构算，不能用一重循环从头加到尾。

### 4.3 Router 的逐级归约

ReduceModule 原位读改写，一次累加一个到达的分量：

```
a = (reduce_data_type == BF16) ? BF16toFP32(flit) : flit
第一个分量：ctx[user][offset] = a
其后每个：  ctx[user][offset] = ctx[user][offset] + a        FP32
```

三条规则：

* 中间累加固定 FP32，与 `reduce_precision` 无关，后者只配输入与输出精度
* BF16 输入先扩宽成 FP32 再加，不在 BF16 上累加
* **按到达顺序累加**。到达顺序由链路与仲裁决定，因此参考实现不能自己定一个顺序：它取模型这一次运行记下的到达顺序

最后一条是三处累加里唯一一处顺序不由配置决定的。模型把每个 `(user_id, offset)` 上分量的到达顺序记进观测产物，参考实现按它复算。

## 5. 参考实现

### 5.1 产出

参考实现算出 `expect_out`：每个 token 一条定长记录，按 token 顺序排成一个二进制文件，由 `.bachir` 的 `EXPECT` 记录登记路径与形状。

### 5.2 与模型共用一份编解码

`reference/` 不重写编解码与累加，它调用与模型同一份 `common/numeric/`。两侧各写一套等价实现，会在舍入与结合顺序上分叉，而这两处的分叉正是逐 bit 比对要查的东西。

`common/numeric/` 对外只出三类函数：格式之间的转换、块格式的编解码、三处累加各自的归约函数。模型与参考实现都不在这三类之外自己写浮点运算。

## 6. 本文件定的默认取法

下面几项设计只给了原则没给细节。模型按这里的取法实现，向设计方要到细节后只改 `common/numeric/`，不改模型其余部分。全部标“待定”。

| 项 | 默认取法 |
| --- | --- |
| CSA 树在一个 scale block 内的形状 | 按下标两两配对的平衡二叉树，块长 32 时五级，块长 16 时四级 |
| 跨 scale block 的累加顺序 | 按 block 下标从小到大依次累加 |
| `ROUND_MODE` 3 bit 的取值枚举 | `0` 就近偶数、`1` 向零、`2` 向正无穷、`3` 向负无穷、`4` 就近远离零，其余编码按 `0` 处理 |
| 随机舍入是否实现 | 不实现。`ROUND_MODE` 没有它的编码 |
| `NVFP4` 与 `MXFP4` 的差别 | 两者按同一套编解码实现。差别待设计方给出后再分开 |
| MU 的 Clamp 边界 | NaN 取目标格式的正 NaN，Inf 取目标格式的最大有限值 |
| `reduce_precision` 2 bit 的取值枚举 | `0` 输入输出都 BF16、`1` 输入 BF16 输出 FP32、`2` 输入 FP32 输出 BF16、`3` 输入输出都 FP32 |
